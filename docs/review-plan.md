# План code review: модуль src/discount.py

## 1. Цели ревью
- Точность расчётов: порядок применения скидок и итоговая цена.
- Защита от фрода: невозможность уйти ниже минимальной цены.
- Корректность обработки промокодов и уровней лояльности.

## 2. Измеримые критерии
- [ ] Отсутствие «магических чисел»: все коэффициенты и пороги вынесены в именованные константы.
- [ ] Валидация входных данных: `cart_sum >= 0`, `promos` — итерируемый объект, `tier` ∈ {0, 1, 2}.
- [ ] Покрытие тестами > 80% (измеряется через coverage).
- [ ] Все ветвления (if/elif/else, цикл) покрыты хотя бы одним тестом.
- [ ] Нет неиспользуемых импортов и нарушений flake8.

## 3. Участники и роли
| Роль | Ответственность |
|---|---|
| Автор | Подготавливает PR, отвечает на замечания |
| Ревьюер (Tech Lead) | Проверяет логику, граничные случаи, запахи кода |
| Владелец кода (@HighSkillScama) | Финальный аппрув через CODEOWNERS |

## 4. Эскалация
- Если автор и ревьюер не пришли к согласию после **двух итераций**, вопрос выносится на Tech Lead / тимлида.
- Если блокирующее замечание не исправлено после **трёх итераций**, PR не сливается, а задача возвращается в бэклог с описанием риска.d
